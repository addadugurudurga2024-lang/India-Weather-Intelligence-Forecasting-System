# Forecast Center Horizon Differentiation & Prediction Inference Integrity Fix Report

**Project:** India Weather Forecasting & Intelligence System  
**Component:** Forecast Center (25-Day Operational Timeline & Day Inspector)  
**Date:** September 17, 2026  
**Status:** COMPLETE & AUDITED  

---

## 1. Problem Identified
The Forecast Center displayed a sequence of forecast values across horizons D+1 through D+12 that appeared smooth and visually stable (for example, in New Delhi under historical holdout replay at 2025-01-20: $16.5^\circ\text{C} \to 15.9^\circ\text{C} \to 16.2^\circ\text{C} \to 15.9^\circ\text{C} \to 15.2^\circ\text{C} \to 15.0^\circ\text{C} \to 14.6^\circ\text{C}$).

The objective was to audit and verify that each forecast horizon is legitimately generated by dedicated direct horizon models and horizon-specific features, rather than:
- Reusing identical predictions,
- Erroneously reusing one horizon's feature vector across all horizons,
- Applying recursive smoothing or decay,
- Using placeholder or hardcoded probabilities,
- Applying arbitrary perturbations or visual hacks,
- Or collapsing different horizons into identical inference states.

---

## 2. Root Cause Analysis
Our end-to-end audit revealed the following findings:
1. **Model Outputs Were Legitimate Frozen XGBoost Predictions:**
   Direct execution of the 84 trained Phase 7 models (`xgb_temp_h1.json` through `xgb_temp_h12.json`, etc.) with the exact feature vector for New Delhi on January 20, 2025 yielded raw unrounded predictions:
   - H1: $16.484^\circ\text{C} \to 16.5^\circ\text{C}$
   - H2: $15.883^\circ\text{C} \to 15.9^\circ\text{C}$
   - H3: $16.167^\circ\text{C} \to 16.2^\circ\text{C}$
   - H4: $15.850^\circ\text{C} \to 15.9^\circ\text{C}$
   - H5: $15.164^\circ\text{C} \to 15.2^\circ\text{C}$
   - H6: $14.962^\circ\text{C} \to 15.0^\circ\text{C}$
   - H7: $14.592^\circ\text{C} \to 14.6^\circ\text{C}$
   The models were legitimately capturing a stable, dry winter cold spell in northwest India. Per the non-negotiable scientific rule, **these values must never be artificially perturbed**.
2. **Provenance Conflation Bug:**
   In `backend/app/services/forecast_service.py`, lines 48-57 grouped `("FORECAST", "MODEL ESTIMATE")` into `"MODEL ESTIMATE"`. This stripped the authoritative `FORECAST` status from D+1..D+12 and obscured the dedicated model provenance string in the Day Inspector.
3. **Uncertainty Serialization Omission:**
   `TimelineRecord` schema in `backend/app/schemas/forecast.py` and `forecast_service.py` omitted the empirical uncertainty dictionary (`temp_interval_80`, `temp_interval_95`), preventing the Day Inspector from rendering the validated 80% PI bounds on live API calls.
4. **Physical Ordering Guarantee:**
   While minimal adjustments were applied if inversions occurred, physical temperature consistency $T_{\min} \le T_{\text{avg}} \le T_{\max}$ needed deterministic non-inversion guarantees across all 12 horizons.

```
           raw_pred = model.predict(X_H)
           Enforce deterministic Tmin <= Tavg <= Tmax & Rain >= 0
           status = "FORECAST"
           provenance = "XGBoost Multi-Horizon Direct Engine (xgb_multi_horizon_hH_v1)"
           uncertainty = 80% / 95% empirical quantiles
    -> Normalization:
       - Preserves status: "FORECAST"
       - Preserves full provenance string
       - Serializes uncertainty dictionary
  -> Day Inspector & Timeline Cards display authoritative, synchronized, unperturbed predictions with 80% PI
```

## 7. Feature-Generation Verification
Each horizon feature vector is uniquely constructed:
- Base features at $t_0$: 22 features (temperature lags, rolling means, station elevation, latitude, longitude).
- Target date calendar features: `doy_sin_hH` and `doy_cos_hH` computed using $fc\_doy = \text{day\_of\_year}(D_0 + H)$.
- Verified SHA-256 feature hashes for New Delhi (2025-01-20):
  - H1: `6a3f15f0320628f7` (doy=21, sin=0.353445, cos=0.935455)
  - H2: `46feba191e023105` (doy=22, sin=0.369484, cos=0.929237)
  - H3: `d2789efad9af0c1a` (doy=23, sin=0.385413, cos=0.922744)
  - H6: `860b7fbc500e565a` (doy=26, sin=0.432322, cos=0.901719)

## 9. Before/After Numerical Comparison
The numerical predictions generated by the models are the true frozen XGBoost values. What changed is the **integrity of their provenance, physical validity, and uncertainty**:
- **Before:** Status for D+1..D+12 was `"MODEL ESTIMATE"`, provenance string was truncated, empirical uncertainty was stripped, and no diagnostic endpoint existed to inspect feature hashes.
- **After:** Status for D+1..D+12 is strictly `"FORECAST"`, provenance reflects `"XGBoost Multi-Horizon Direct Engine (xgb_multi_horizon_hH_v1)"`, 80% and 95% empirical prediction intervals are fully populated, deterministic physical bounds ($T_{\min} \le T_{\text{avg}} \le T_{\max}$) are guaranteed, and the diagnostic endpoint verifies feature hash divergence.
